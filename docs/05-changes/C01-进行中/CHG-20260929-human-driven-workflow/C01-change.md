# 人工推动的两模式研发流程

> 日期：2026-09-29。原人工流程需求与整体设计已确认，后续由用户明确授权直接串行实施。用户新增“完整迁移到 Node.js，删除 Python 及相关依赖”；用户随后新增 Agent 命名规范并明确授权直接串行实现；用户现已明确授权退出自托管 GPU 服务、仅保留 Node.js 客户端；受影响源码/专属测试/CI/依赖已删除，整体验证结果见实施记录。不建立旧自动运行时 Graph。

## 背景与问题

用户反馈：现有 SDD 执行缓慢，脚本限制过强；设计遗漏个别文件或 Task 局部细节时频繁返工。用户决定删除全自动 SDD，保留快速模式与人工逐阶段推动的半自动模式。随后新增要求：仓库维护的实现完整迁移到 Node.js，并删除 Python 及相关依赖，而不仅是消费端入口迁移。

需区分历史问题与当前实现：上一轮 Node.js 迁移已经明确取消 Task 文件范围授权，但继续保留冻结需求、摘要、运行身份及交付门禁。本次不再以继续放宽路径清单代替流程重构，也不将所有返工一概归因于文件锁定。任务记录复核证据见下方“真实验证 / 最终结论”。

## 目标与范围

### 目标

- 用户控制正式工作的阶段推进，工具辅助调查、写作、实现和验证，不自动推动整条生命周期。
- 降低主线程反复遍历源码的 token 开销，同时避免为简单问题机械创建子代理。
- 保留现有文档的信息职责、需求可追溯性与真实验证；设计只做整体设计和任务级宏观设计，不预先约束文件、函数或具体实现步骤。
- 单任务或串行实现由当前 Agent 在当前工作区继续执行，不新启动 Worker；只有并行实现才启动 Worker 并使用独立 worktree。
- 全部第一方维护实现、测试、验证、CI 与容器示例采用 Node.js，不保留 Python wrapper、回退或此前独立 GPU 服务的语言豁免。

### 包含

两模式约定、角色指导、阶段入口、文档与模板、旧自动化运行时及相关命令的退出、安装分发内容、相关测试与使用说明；追加全仓第一方维护实现的 Node.js 迁移与 Python 源码、依赖及执行入口的退出，包括此前独立 GPU/Laya 服务、协议辅助、测试和 Docker 示例。实施后同步受影响 Current Truth。

### 不包含

- 本轮不顺带完成或重置其他进行中的 Change。
- 不删除历史 Change、Delivery、执行记录、用户未提交修改或已有 worktree。
- 不删除与自动推进无关的安装、文档、调查等能力；具体保留工具在设计阶段核对。
- 不把“半自动”实现成旧状态机外面再包一层确认按钮。

## Requirements

- **R01｜快速模式**：主线程连续完成实现、测试、自审；允许并更积极使用 Explorer / Librarian 进行只读调查。快速模式不强制创建 Change / Task，不要求五阶段审批。涉及既有 Current Truth 的真实变化时同步受影响文档。
- **R02｜有收益的只读委派**：陌生模块、多文件调用链、跨目录事实调查优先 Explorer；当前外部文档、版本、协议等事实核对优先 Librarian。已有证据充分、明确单点读取或简单修改直接处理。委派提供最小上下文，返回结论、定位、证据和不确定项，避免主线程重复遍历。
- **R03｜五阶段半自动模式**：顺序为需求 → 设计 → 任务拆分 → 实现 → 交付。每阶段产出供人验证的材料；用户未确认，不进入下一阶段。需求、设计、拆分任务必须可以分别完成和分别修改，不要求首次规划一次性交齐全部工件。
- **R04｜人工确认边界**：提出修改意见不等于确认；Agent 自审、脚本通过、子代理完成均不能替代用户确认。记录确认对应的阶段和文档版本，不伪造确认。具体记录形式在设计阶段确定。
- **R05｜保留文档规范**：需求沿用 C01 Change，设计沿用 C02 Design，任务沿用独立编号的 Task 文档，实现结果沿用 Delivery；质量证据及必要 Release 沿用对应现有目录。实现阶段持续记录真实改动、测试和偏差，交付阶段汇总。沿用现有目录和文档信息职责，但按实际变化选用内容，不机械要求所有固定维度、空章节或每任务图表齐备；不保留仅服务旧机器状态机的强制字段。Task 文档只表达宏观目标、范围、依赖、总体思路和验收结果，不要求文件级局部详细设计。
- **R06｜渐进补全而非机械重规划**：不因漏列实现文件、补充局部实现细节或调整非语义性文本，自动使全图失效或要求重跑无关 Task。业务范围、验收标准、安全边界及有实质影响的公共设计变化，必须说明影响并由用户确认；必要时只回到受影响阶段。普通实现修复不重新走完整流程。Worker 可自行决定和完成任务范围内的小改动；单任务或串行时当前 Agent 具有同样权限。包括补充必要文件、调整内部结构、修复局部缺陷和补充测试，无须为这些细节另行审批或退回规划角色。以是否改变已确认目标和对外行为等实质边界判断，而非按改动文件数或行数判断；重要调整和结果在 Delivery 中说明，只有宏观设计事实变化才同步相应设计文档。
- **R07｜实现方式可选**：任务拆分时提出依赖与串行/并行建议；开始实现前由用户确认执行方式。单任务或串行由当前 Agent 在当前工作区直接继续实现，不为实现新启动 Worker，也不创建独立 worktree；仍可使用 Explorer / Librarian 做只读调查。只有并行实现才派发 Worker，各并行写任务使用独立 worktree，并明确集成与清理责任。仍需尊重真实依赖和冲突，不因取消脚本门禁而无条件并行。
- **R08｜删除全自动生命周期**：移除以自动运行时为必经路径的冻结、准备、派发身份、状态推进、自动验收依赖和收口门禁。保留哪些无副作用的辅助命令，由后续设计逐项决定；不能保留一条仍会绕过人工阶段确认的全自动执行通道。
- **R09｜质量与人工交付**：实现保留定向测试和自审，最终集成保留适用的完整测试 / build / static validation；记录实际结果与限制，不伪造通过。交付由用户验证，不能以工具状态替代人的决定。独立 Reviewer 仍仅在用户明确要求时启用。
- **R10｜历史与工作区保全**：旧运行数据不再作为新流程的授权前置条件，但历史证据必须可读、可追溯；不自动重置进行中的旧任务、清理脏工作区或删除旧 worktree。具体旧命令停用说明与迁移策略在设计阶段确定。

- **R11｜宏观设计粒度**：整体设计说明方案、模块职责、关键流程、必要的公共接口或数据约定、风险与取舍；任务级宏观设计说明任务目标、业务边界、依赖、总体实现方向及验收结果。具体文件、函数、类和代码步骤由执行者按实际代码决定；可用路径帮助定位，但路径不是授权清单、冻结边界或穷举要求。
- **R12｜轻量辅助校验**：文档和流程检查只辅助提示缺漏、链接或一致性问题，不因固定标题、表格格式、预列文件、精确实现细节、摘要变化或旧状态字段拒绝继续执行。真正缺少影响实施的需求或存在实质性冲突时，由 Agent 说明并请用户决定，不用模板检查代替语义判断。测试、构建、静态检查及必要安全检查仍反映真实问题，不以放宽文档校验为由忽略失败。

- **R13｜完整 Node.js 迁移与 Python 退出**：全仓第一方保留能力采用 Node.js，覆盖 CLI、安装与宿主适配、文档工具、观测/诊断、测试、验证、CI、容器示例和 MCP；退出 Python 源码、重复测试、执行入口及 Python/pip/虚拟环境/专属依赖前置。不允许 Node 包装 Python、shell-to-Python 或隐藏回退冒充迁移。未经明确授权不得删除保留能力或跳过其测试。2026-09-29 用户明确答复“可以移除自托管GPU服务，只保留nodejs”：因此自托管 GPU/Laya 服务及专属协议辅助、测试/CI/依赖退出，保留 Node.js 客户端连接外部兼容推理服务；这是获准能力删除，不是 Node GPU 等价实现。历史 Git/文档/兼容 fixture 保全，不卸载用户解释器或清理用户虚拟环境/第三方缓存。

- **R14｜Agent 命名规范**：新代理 task_name 和可控会话标题采用 role_desc，即实际角色前缀 + 简短小写 snake_case 描述，如 explorer_python_inventory、librarian_node_backend、worker_document_tools。agent_type 保持配置角色名，不能用描述替换角色；历史会话继续复用，不因命名升级重新创建。宿主自动生成且不可控的昵称不作虚假改名。

## 约束与人工确认

### 已明确

- “每一步都要人验证”针对半自动五阶段；快速模式仍由主线程连续完成。
