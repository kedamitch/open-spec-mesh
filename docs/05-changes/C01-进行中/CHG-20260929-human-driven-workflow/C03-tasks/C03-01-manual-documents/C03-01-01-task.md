# C03-01｜人工流程与渐进文档

> 用户已授权直接串行实施，由当前 Agent 在当前工作区执行；无需 Worker 或 worktree。本 Task 为宏观设计，实际结果与验证见 Delivery。GPU 能力退出已由用户明确确认；本 Task 不代替整体实际验证与最终人工验收。

## 目标

让当前 Agent 能按 Quick 或人工确认的五阶段流程工作，且需求、设计和任务拆分可以独立产出，不被旧完整规划协议绑住。

## 范围与分工

- 两模式工作约定、角色说明、Dispatch Packet、Skills 与写作模板采用已确认的宏观设计和执行自由度。
- Quick 更积极使用有收益的 Explorer / Librarian 只读调查；半自动阶段推进等待人工确认。
- 单任务或串行由当前 Agent 执行；仅并行派发 Worker；Architect 可选、Reviewer 仅按用户明确要求使用。
- 文档脚手架按阶段创建 Change、Design、Task 与人可读任务计划，不要求后续工件齐备、不生成执行 Graph 或空 Delivery。
- 文档格式和结构检查作为辅助提示，保留通用路径、原子写入、资源锁与资产保护。

旧生命周期的实际删除由 C03-02 负责；观测和可选语义工具行为由 C03-03 负责；宿主安装消费一致性由 C03-04 验证。这里先更新生成来源与文档能力，不把计划写成 Current Truth。

## 输入与依赖

输入为已确认 C01 Change 和 C02 Design，无其他业务任务前置。输出的模式语义、文档结构和通用读取约定供后续能力消费。

公共方案见 [整体设计与 Node.js 迁移范围](../../C02-design.md)，执行方式见 [任务计划](../C03-task-plan.md)。

## 总体实现方向

以现有文档工具和角色/Skill 体系为基础渐进调整，不重新建立审批运行时。文档生成只做显式请求的工作，检查不通过模板完整性判断业务授权。保留 sdd-* 命名可减少无关迁移，但其内容必须退出旧自动语义。

具体文件、函数、模块整理与编码步骤由执行者按真实调用链决定。任务内的小调整可自行完成，重要调整写入 Delivery；只有实质业务或公共边界变化才请用户确认。

## 验收与验证方向

- Quick 无须正式工件即可交付；五阶段停止点清楚，Agent/工具结果不会被当作用户确认。
- 仅 C01 存在、仅整体设计完成或仅宏观任务完成均为正常阶段，不因缺少后续工件而被拒绝。
- 任务文档没有文件白名单、函数清单或强制逐步方案；局部实现调整不要求重审批。
- 格式告警不会阻断流程，非法路径、覆盖未受管资产和真实读写错误仍得到安全处理。
- 用文档脚手架、编号/导航、角色与生成指导的相关回归证明上述行为；结果写实际 Delivery。
