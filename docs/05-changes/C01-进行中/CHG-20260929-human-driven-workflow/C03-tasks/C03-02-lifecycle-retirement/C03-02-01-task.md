# C03-02｜退出自动生命周期

> 用户已授权直接串行实施，由当前 Agent 在当前工作区执行；无需 Worker 或 worktree。本 Task 为宏观设计，实际结果与验证见 Delivery。GPU 能力退出已由用户明确确认；本 Task 不代替整体实际验证与最终人工验收。

## 目标

实际删除全自动 SDD 的公开入口和运行时链路，让保留能力能在没有冻结、执行 Graph、Worker 身份和验证 receipt 的情况下工作。

## 范围与分工

- 移除已确认设计中的生命周期命令、冻结/漂移传播、自动状态写入、prepare、会话绑定、自动交付/验收、wave 集成与 receipt 归档链。
- 帮助和保留能力不再把旧命令作为前置；旧调用明确失败并指向人工流程，不使用成功 no-op 或隐式自动兼容。
- 发布材料生成和检查解除 workflow contract/closure 依赖，所需通用文档读取归入保留能力。
- 验证直接执行项目实际命令；文档中的 pass 或旧 receipt 不证明用户确认和真实验证。
- 通用资源锁、路径/文本/文档处理、Git 查询等能力按实际用途保留；不得按 graph/sdd 文件名批量清除历史读取。

不删除历史 Change、Graph、Delivery、SQLite、receipt、Git history 或已有 worktree，不重置其他旧 Change。观测和语义策略兼容由 C03-03 完成；消费包与统一质量入口由 C03-04 完成。

## 输入与依赖

消费 C03-01 已落实的文档职责与通用读取约定。若运行时内部被其他保留能力引用，迁移必要通用能力而不是留下整套自动状态机。

公共方案见 [整体设计与 Node.js 迁移范围](../../C02-design.md)，执行方式见 [任务计划](../C03-task-plan.md)。

## 总体实现方向

先区分自动写入/授权与通用读取，再断开入口和调用依赖。保留命令仍应可独立加载和执行，不引入同名新状态机。测试有意删除行为时转为验证退出和保全，不继续要求旧自动协议通过。

具体文件、函数、模块整理与编码步骤由执行者按真实调用链决定。任务内的小调整可自行完成，重要调整写入 Delivery；只有实质业务或公共边界变化才请用户确认。

## 验收与验证方向

- 旧自动命令不再可执行；没有隐藏入口恢复冻结、派发、验收、集成或归档状态链。
- 保留 CLI、发布材料和资源锁工具无需旧 Graph 或冻结字段，且仍安全处理非法调用和故障。
- 文档轻微变化、补充实现文件不会再通过旧摘要导致 replan 或验收身份失效。
- 既有历史工件和用户工作区保持可追溯，不因退出命令而被自动清理。
- 用 CLI、发布材料、通用锁及相关保留能力的定向测试验证，明确记录哪些自动化场景有意退出。

## 预期交付

实际能力改动、定向验证证据、必要自审与修复、剩余问题及快照影响。完成后创建 `C03-02-02-delivery.md`，不提前生成空报告，也不借助旧冻结或状态机证明完成。
