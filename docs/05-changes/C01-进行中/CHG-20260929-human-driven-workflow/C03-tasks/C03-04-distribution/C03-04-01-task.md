# C03-04｜安装分发与质量入口一致

> 用户已授权直接串行实施，由当前 Agent 在当前工作区执行；无需 Worker 或 worktree。本 Task 为宏观设计，实际结果与验证见 Delivery。GPU 能力退出已由用户明确确认；本 Task 不代替整体实际验证与最终人工验收。

## 目标

让用户安装或升级后实际获得新流程，而不是仓库文案已更新、宿主与消费包仍在推广或执行旧生命周期。

## 范围与分工

- 三宿主配置渲染、受管安装与升级分发前三项的新角色/Skill/CLI 能力，保留用户模型与未受管资产。
- 安装资源、依赖、公开帮助、README、使用指南和 tarball 内容采用同一能力集合；不再把旧自动脚本当作消费前置。
- 调整项目质量入口、测试清单和覆盖说明，移除已退出自动能力的强制校验，覆盖新的人工流程和保留能力。
- 通过真实隔离消费 smoke 验证安装、文档辅助与需要保留的公开工具，避免仅验证内部模块。

不公开发布 npm 包、不执行真实部署、不认证 Provider 或要求真实模型调用；不升级无关依赖或清理用户既有资产。最终 Current Truth 同步和用户验收归档由当前 Agent 在交付阶段完成。

## 输入与依赖

需要 C03-01 的生成指导与文档能力、C03-02 的最终公开入口和通用工具、C03-03 的兼容观测/语义能力全部真实可用。消费验证不能以未实现的计划替代。

公共方案见 [整体设计与 Node.js 迁移范围](../../C02-design.md)，执行方式见 [任务计划](../C03-task-plan.md)。

## 总体实现方向

沿用现有安装 ownership、配置保全和回滚机制，更新受管资源与宿主语义。整体质量检查验证目标能力，不再维护旧 Graph readiness、固定迁移计数或 receipt 的流程门禁。对有意退出的行为说明替代检查，不把保留能力的失败当作存量豁免。

具体文件、函数、模块整理与编码步骤由执行者按真实调用链决定。任务内的小调整可自行完成，重要调整写入 Delivery；只有实质业务或公共边界变化才请用户确认。

## 验收与验证方向

- Codex、OpenCode、Claude Code 的生成配置一致表达两模式、人工确认、当前 Agent 串行与并行 Worker 隔离。
- 消费包和帮助没有旧自动执行通道，辅助工具可用，未受管资产、用户配置和历史数据得到保全。
- 文档检查告警与真实安全/工程错误区分清楚；质量入口不会因新流程缺少 Graph/身份而阻断。
- 安装/升级/回滚、宿主渲染及隔离 tarball smoke 的相关定向验证通过。
- 向整体实现结果提供可复验的命令、环境、实际退出结果与未验证项；项目全量验证由当前 Agent 收敛执行，不在每个 Worker 中重复。

实际能力改动、定向验证证据、必要自审与修复、剩余问题及快照影响。完成后创建 `C03-04-02-delivery.md`，不提前生成空报告，也不借助旧冻结或状态机证明完成。
