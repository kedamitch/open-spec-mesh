# C03-02｜安装器与模型配置

## 目标与范围

段 B：让 `osm install --host dsh` 只声明并写出 DSH 真正消费的产物，让模型配置只剩一份事实源，并让 CLI 的提示与校验责任说清。范围是 `lib/installation/models-config.js`、`lib/installation/installer.js`、`lib/installation/inspect.js`、`lib/cli/models.js`，以及 `dsh/gatekeeper.mjs` 改为引用单一事实源。对应设计 B1–B4，见 [根因与设计](../../C02-design.md)。

## 输入与依赖

- 依赖 C03-01：本段要改 `dsh/gatekeeper.mjs` 的 import，必须先有重写后的文件。
- 宿主事实（只读）：技能扫描根 `$DSH_HOME/skills`（`dsh-skill-filesystem/lib/index.js:171`，另有 `:154`/`:159`/`:176`）；instructions 走项目 `AGENTS.md`。
- HEAD 的角色模型值（提交 `1b9ec08`、`96ac9a1`）是本段的既有输入，不重新设定。

## 交付输出

单一事实源 + 诊断函数；`--host dsh` 的写入/跳过/fail-closed 语义；inspect 的 dsh 口径；CLI 提示与空值拒绝；对应定向测试（`models-config.test.js`、`install-dsh.test.js`）。

## 任务级设计

### 总体实现方向

把"安装器写什么"与"宿主读什么"对齐：DSH 读 `AGENTS.md` 与 `$DSH_HOME/skills`，就只写这两项，其余分支显式排除而不是静默跳过。模型配置只保留 `lib/installation/models-config.js` 一份，插件通过 import 使用；坏输入记 problem 而不是回落默认值。

## 验收与验证方向

- `node --test tests/node/dsh/models-config.test.js tests/node/dsh/install-dsh.test.js` 通过。
- 静态检查：dsh 分支不再落入 MCP overlay 路径（历史 bug 见 `lib/installation/host-adapter.js:154`）。
- `--with-laya` 在 dsh 上写入前 fail closed（`lib/installation/installer.js:534`）。
- 不声称安装器全流程已在无 node_modules 的环境跑通，见 C04 未验证清单。
