# 协作效率优化

## 背景与目标

用户在使用中遇到多 Agent 上下文交接、沟通和细设计返工成本抵消模型分层收益的问题。本次降低完整任务的协作与返工成本，不以代理数量或文档页数作为成果。

## 范围与约束

- 以 [已确认优化表](C02-design.md) 的 A1–A8、B1–B5、C1–C5 为设计输入，优化协作规则、模板、安装边界、观测与验证。
- 完整保留 docs/01–09、C01/C02/C03、独立 Task、Delivery 和导航；不重写或删除历史 Change、Graph、交付与发布证据。
- 维持 Quick / 人工 SDD、人工确认、只读职责、明确并行授权；串行由当前 Agent 实施，不启动 Architect/Worker，不创建 worktree。
- 不调整模型，不增加自动调度器或生命周期，不恢复 Graph/attempt/审批 token，不自动提交、推送、发布或归档。
- 保全用户现有 AGENTS.md 第 7 节等未提交内容；本仓库专用规则不得进入下游默认安装。
- 真实多模型大规模成本评测不在本次默认执行范围；仅准备可复用的小规模对照方案，未知数据不得写成节省。

## 可观察验收

1. AC1：通用规则和各角色明确净收益委派、连续执行、三类设计信息、局部升级及验证责任；局部修改无需额外模型判断或强制代理。
2. AC2：独立 Task 和 Delivery 结构保留；信息职责明确，简单任务短写、共享事实引用复用，不生成空壳或空报告。
3. AC3：安装与升级使用通用单源规则，各宿主不混入本仓库发布信息；用户自定义内容保全；共享副本有真实一致性检查。
4. AC4：无 Graph 正常流程中的历史返工指标显示不适用/未知，不显示虚假的零返工；用量按会话去重并报告覆盖，价格缺失不输出金额。
5. AC5：提供按需、只读且不暴露秘密的宿主文件配置核验；显式区分文件期望与当前活动会话未知。
6. AC6：新增行为场景测试和固定基线的小规模效果对照方案，区分静态、fixture 与真实模型证据；适用回归与全量 core 通过或如实记录失败。
