# 协作效率优化｜已确认设计

本文件保留用户在 2026-09-30 确认的优化表。信息职责去重、按需展开和引用复用是方案，不通过删除文档结构来简化。授权来源见 [需求与确认](C01-change.md)。

## 必须保留的边界

- 保留 docs/01–09 完整结构及现有导航。
- 保留 Change 内的 C01 需求、C02 整体设计、C03 执行计划、独立 Task、Delivery。
- 保留 Current Truth、ADR、Research、Quality、Release 各自职责。
- 不删除、不改写历史 Change、Graph、交付和发布证据。
- 保留 Quick / 人工 SDD 两种模式，不增加自动生命周期。
- 保留人工确认和并行授权边界；不把工具通过当作批准。
- 保留当前模型配置；先减少无效工作，再依据数据判断是否调整模型。
- 保全现有 AGENTS.md 未提交修改，不覆盖用户内容。

文档结构完整，不等于每份文档重复完整背景；宏观设计完整，也不等于预先确定所有实现细节。

## A. 直接降低协作与返工成本

| 编号 | 优化项 | 目前的问题或风险 | 具体调整 | 涉及范围 | 验收标准 |
|---|---|---|---|---|---|
| A1 | 委派前判断净收益 | “陌生、多文件”容易成为机械委派理由，未充分考虑交接成本 | 增加简短判断：是否能压缩大量调查材料、获得真实并行收益，或解决明确的专业风险；已有上下文充分、说明成本接近执行成本时直接处理。不额外调用模型来判断是否委派 | 通用工作约定、派发契约、角色说明 | 明确的局部修改不要求启动代理；大范围定向调查仍可委派；文件数不作为自动拆分条件 |
| A2 | 保持执行责任连续 | 调查、设计、编码、修复反复换人，导致上下文重建 | 串行由 Main 完成完整闭环；并行 Worker 自主完成调查补充、实现、定向验证、自审与修复。同一目标优先复用原会话，不为流程步骤换角色 | agents/*.toml、sdd-do、派发契约 | 普通修复不重新启动 Architect 或新 Worker；仍严格保留只读角色和并行授权边界 |
| A3 | 设计区分约束、方案、假设 | “宏观设计”虽已有规定，但哪些内容可以调整仍容易解释不一 | 明确三类信息：必须遵守的行为/安全/公共契约；执行者可调整的实现方案；尚待验证的假设。不要求简单设计填写固定三张表 | sdd-design、sdd-plan、相关模板及写作参考 | Worker 调整文件、函数、内部组织不触发重规划；改变验收、安全或重要公共契约才升级 |
| A4 | 不确定性前置验证 | 上游假设未经验证就进入后续任务，发现错误时连锁返工 | 在设计和计划中指出会影响后续工作的关键未知；优先安排最小验证。设计阶段仅做授权范围内的调查/隔离验证；实施获授权后先打通关键路径，再展开依赖它的工作 | 设计、执行计划、任务模板、实现技能 | 未验证假设不写成事实；依赖假设的任务不伪装成已具备并行条件；不新增强制 Spike 阶段或角色 |
| A5 | 局部变化只处理局部影响 | 执行中发现问题可能被扩大成全阶段返工 | 给出清晰升级边界和例子：内部实现变化自行处理；任务间契约变化协调受影响任务；目标、验收、安全等实质变化请用户决定。保留未受影响的成果与验证证据 | Worker、Architect、sdd-do、文档契约 | 局部修复不要求重写全部设计、重做全部任务或重新批准未变化内容 |
| A6 | 明确验证责任与复用条件 | Worker、Main、Reviewer 可能重复运行同一套检查 | Task 说明定向验证方向；Worker 执行定向验证；Main 负责整体集成验证。只有代码、环境或依赖变化使证据失效，或原证据不足时，才补跑重叠验证 | 派发契约、任务模板、实现与交付技能 | 不降低测试要求；不以“已经测过”为由跳过受集成影响的检查；避免每个子任务反复跑全量 |
| A7 | 区分查询、取结果和继续执行 | 查看进度或结果时可能误触发新一轮推理；结果缺失时容易重复派发 | 明确状态查询、读取已有结果、发送增量任务的不同语义；恢复前检查已有结果。同一目标只传增量，不重发整份上下文；按实际宿主能力映射 | 派发契约、角色恢复说明、宿主适配指引 | 查结果不被描述成继续执行；不虚构宿主没有的工具；不移植复杂后台调度器 |
| A8 | 复审聚焦真实差异 | 复审容易重新讨论已确认、未变化的设计，形成循环 | 仅在用户要求独立复审时启用 Reviewer；优先检查真实 diff、未解决问题及修改引入的风险。复审不因格式偏好重开已接受决策；反复未收敛时报告原因 | Reviewer、交付指引 | 不增加默认复审阶段；修复后不无理由重新审查全部内容；实质安全与正确性问题不能因控制成本而忽略 |

## B. 保留完整文档结构，同时减少重复写作

| 编号 | 优化项 | 保留什么 | 具体调整 | 涉及范围 | 验收标准 |
|---|---|---|---|---|---|
| B1 | 明确各文档的信息归属 | C01、C02、计划、独立 Task、Delivery 全部保留 | C01 负责目标与验收；C02 负责共享方案与公共约定；计划负责任务关系与执行安排；Task 负责本任务差异、输入输出与验证；Delivery 记录实际结果。引用已有事实，不重新复述 | 文档契约、各阶段技能和模板 | 同一需求或公共设计不要求在多份文档重新描述；跨文档引用可定位、无矛盾 |
| B2 | Task 保持独立，但按复杂度展开 | 独立 Task 目录、编号、文档和导航不变 | 简单任务短写；并行或高风险任务补充必要细节。引用共享设计，同时保留足够的任务目标、约束和验收信息，避免变成只有链接的空壳 | 任务模板、new-task 相关测试 | 目录结构与命令兼容；简单任务无需填充不适用章节；执行者能准确识别任务边界 |
| B3 | Delivery 只记录实际增量 | Task Delivery 与整体交付记录保留 | Task Delivery 记录本任务改动、验证、重要偏差和风险；整体交付汇总跨任务结果与集成验证，不复制所有 Task Delivery | sdd-do、sdd-close、文档契约 | 不预生成空报告；不重复粘贴测试流水账；失败与未验证项仍清楚可见 |
| B4 | 通用规则与本仓库规则分离 | 本仓库 AGENTS.md 的专用发布说明及历史记录保留 | 安装器使用明确的通用规则来源，不再把本仓库完整 AGENTS.md 当作所有下游宿主的默认规则；同步检查各宿主适配入口 | 安装器、host adapter、通用规则来源、安装回归测试 | 新安装和升级后的通用规则不混入本仓库 owner、workflow 和发布历史；用户自定义规则仍保全 |
| B5 | 共享规则单源维护 | 现有模板、参考文档和宿主所需文件路径保留 | 为重复规则确定唯一维护来源，必要副本通过生成或一致性检查维护；内容按使用场景分层，不要求 Agent 为一个步骤读取全部规则副本 | 工作流参考、项目模板、生成/验证脚本 | 一处修改能可靠同步必要副本；不靠维护多份近似全文防止漂移；不会扩大默认上下文 |

## C. 补齐效果验证，避免“看似省钱”

| 编号 | 优化项 | 目前的问题或风险 | 具体调整 | 验收标准 |
|---|---|---|---|---|
| C1 | 无 Graph 流程的观测支持 | 新人工流程下，部分任务与返工指标仍依赖旧 Graph | 区分历史 Graph 指标和新流程可观测指标；优先利用现有会话证据统计委派、失败、复用和用量。不能可靠判断的返工保留未知，必要时支持轻量标记 | 无 Graph 不再被误读为零返工；不恢复 Graph、attempt 或审批状态机 |
| C2 | 总成本口径 | 子 Agent 便宜不代表完整任务便宜 | 保留 Main 与子会话用量及覆盖情况，区分输入、缓存输入、输出和耗时；完整成本必须包含派发失败及后续补充。没有实际价格时只报告用量，不估造金额 | 不只展示子 Agent 成本；缺失数据显式标注；不重复累计同一用量 |
| C3 | 增加协作行为场景验证 | 文案正则和确定性 fixture 不能证明真实协作更高效 | 增加代表性场景：无需委派、值得调查、局部变更不升级、公共契约变化升级、复用已有结果、验证责任分工；区分静态检查、运行时测试和真实模型评估 | 测试报告不把“存在某句话”当作模型行为已验证；不把 fixture 通过说成实际节省 |
| C4 | 运行配置一致性核验 | 本次实际派发与仓库模型配置不一致，但根因尚未确定 | 提供安装/升级后的按需核验与诊断指引，检查非敏感的角色、模型和实际运行结果；无法从宿主取得的信息明确标未知 | 不读取凭据、不擅自改用户模型；不将核验放到每次任务前；不声称静态配置通过就代表当前会话已加载 |
| C5 | 小规模效果对照方案 | 缺少直接执行与委派执行的可比结果 | 准备少量固定基线场景与记录方式，对照 Main 直接做、Main 加定向调查、已授权并行三种适用路径。先交付可复用方案，不默认运行昂贵的大规模推理评测 | 同等目标和验收下比较总用量、耗时、补查、返工；不预设多 Agent 一定更优 |

## 实施顺序与不做事项

当前 Agent 串行实施，不建立新的多 Agent 协作链。规则与文档减重 → 安装及规则来源治理 → 观测与验证；每批同步必要测试，不将局部测试拖到最后。

不重新选模型、不新建自动调度器、不增加常驻角色、不恢复机器任务图、不删除独立 Task 文档、不迁移现有文档目录，不承诺未经实际测量的节省比例。
