# C03-01｜诊断内核实现与测试

## 目标与范围 (Goal & Boundary)

- **交付目标**：在 `lib/installation/models-config.js` 中增加模型思考档位白名单与结构化模型诊断接口 `diagnoseModelsConfig(homeDir)`，并提供完整的单元测试覆盖。
- **模块边界**：`lib/installation/models-config.js`、`tests/node/dsh/models-config.test.js`。
- **不做事项**：不改动 `DEFAULT_MODELS` 的既有默认值，不破坏已有 `loadModelsConfigWithDiagnostics` 兼容性。

## 输入与依赖 (Inputs & Dependencies)

- **依赖前置任务**：无。
- **架构方案引用**：[C02 Design](../../C02-design.md) 中的结构化诊断契约与 `VALID_REASONING_EFFORTS` 规范。
- **外部契约与输入**：`DEFAULT_MODELS`、`getModelsConfigPath`。

## 交付输出 (Deliverables)

- 导出常量 `VALID_REASONING_EFFORTS = ['none', 'low', 'medium', 'high', 'xhigh', 'max', 'default']`。
- 导出纯函数 `diagnoseModelsConfig(homeDir)`，返回包含文件存在性、JSON合法性、4角色合规项、issues 与 suggestions 的诊断报告。
- 针对缺失文件、损坏 JSON、顶层非对象、缺少必填项、未知角色、非法档位以及健康配置的单元测试用例。

## 验收与验证 (Acceptance Commands)

- **定向执行命令**：
  ```bash
  node --test tests/node/dsh/models-config.test.js
  ```
