# C03-01｜备份还原内核实现与单测

## 目标与范围 (Goal & Boundary)

- **交付目标**：在 `lib/installation/models-config.js` 中新增模型配置导出 `exportModelsConfig` 与还原 `importModelsConfig` 内核函数，实现严密的格式校验、档位检查与目标文件覆盖保护机制，并建立完备的单元测试覆盖。
- **模块边界**：`lib/installation/models-config.js`、`tests/node/dsh/models-config.test.js`。
- **不做事项**：不改动已有的 `loadModelsConfigWithDiagnostics`、`saveModelsConfig`、`diagnoseModelsConfig` 外部行为；不涉及 CLI 参数解析与终端打印。

## 输入与依赖 (Inputs & Dependencies)

- **依赖前置任务**：无。
- **架构方案引用**：[C02 Design](../../C02-design.md) 中 `exportModelsConfig` 与 `importModelsConfig` 规范。
- **公共契约与输入**：`DEFAULT_MODELS`, `VALID_REASONING_EFFORTS`, `loadModelsConfig`, `saveModelsConfig`, `getModelsConfigPath`。

## 详细任务与交付要求 (Deliverables)

1. **导出函数 `exportModelsConfig(targetPath, homeDir)`**：
   - 目标路径解析：若 `targetPath` 为空，默认为工作区根目录的 `osm-models-backup.json`（`path.resolve(process.cwd(), 'osm-models-backup.json')`）；若指定则自动规范化并递归创建父目录。
   - 读取当前合并生效配置，序列化为 2 空格缩进的 JSON 文件（带结尾换行符）。
   - 返回 `{ success: true, targetPath, config }`。
2. **导入函数 `importModelsConfig(sourcePath, options = {}, homeDir)`**：
   - 解析源文件路径，检查文件是否存在；不存在时返回 `{ success: false, reason: '源文件不存在: ...' }`。
   - 读取并解析 JSON；若解析失败或顶层非对象，返回 `{ success: false, reason: '...' }`。
   - 校验 4 个核心角色（`architect`, `worker`, `explorer`, `librarian`）完备性、必填字段（`provider`, `model` 非空字符串）以及 `reasoningEffort` 是否位于 `VALID_REASONING_EFFORTS`。
   - 覆盖防护门禁：检查目标文件 `getModelsConfigPath(homeDir)`。若已存在且 `!options.force`，则拦截并返回 `{ success: false, blocked: true, reason: '目标配置文件已存在 (~/.dsh/osm-models.json)，若需覆盖请追加 --force 选项。', targetPath }`。
   - 若目标不存在或 `options.force === true`，调用 `saveModelsConfig` 持久化，返回 `{ success: true, targetPath, count: 4 }`。
3. **单元测试（`tests/node/dsh/models-config.test.js`）**：
   - 默认路径导出与自定义路径导出测试；
   - 合法配置成功导入测试（目标不存在）；
   - 目标已存在且未提供 `--force` 拦截测试；
   - 目标已存在且提供 `--force` 强制覆盖测试；
   - 畸形 JSON、缺少角色、缺字段、非法 effort 等校验异常拦截测试。
