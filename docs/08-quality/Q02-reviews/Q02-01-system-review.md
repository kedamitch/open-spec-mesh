# 系统审查与精简

基线：`fc941e5192351f889b71199d0867df8bbfb41936`。范围：流程、角色/Skill 归属、文档模板、生成器、交付/收口校验、初始化、安装与测试约束。保留现有模式、人工门、模型路由和运行协议，不引入新编排框架。

## 发现与处理

| 问题 | 改进 |
| --- | --- |
| sdd-do 残留按技术标签自动升级的旧信号，Task 协议也曾把未冻结视为可直接升级 | 统一用户批准的候选流程；模式与契约变更分别确认 |
| 路由、提示词、Skill、README 反复维护同一长规则 | 分层归属；保留局部必要停止指令，详细策略只引用 |
| 模板以占位段落为主，缺少可验场景 | Change 用 AC / 条件 / 结果 / 验证；Design 写决策/边界；Task 只定义执行切片 |
| Research/ADR/Release 生成器内嵌旧章节，模板改动不生效 | 生成器读取单一模板，测试比对实际生成字节 |
| 项目初始化重复写入全局角色约定 | 项目 AGENTS 只保留本项目验证入口和工程事实，读取独立短模板 |
| 嵌套编号只取前缀，补建缺失 T05-02 被 T05-01 误判冲突 | 比较完整编号，测试缺槽修复和同槽冲突保护 |
| 初始化先更新子索引再创建文件，部分导航遗漏新文件 | 文件创建后按层级刷新索引，测试每个文件均可导航 |
| Delivery 文件表可以从代码示例中被误识别 | 仅可见表格算记录，新增真实 Git 差异回归 |
| 注释或 pending/TBD 可充当非空验证证据 | 拒绝空、纯注释、占位证据；保留合法代码块结果 |
| Prompt 测试要求逐字保留长句，文案精简即失败 | 改测角色/Skill 路径、安装转发、结构预算及执行行为 |
| 主流程图在未批准分支后仍可能向下执行 | 添加明确 break 和集成失败停止路径 |

## 刻意不做

不替换整个 SDD 工具；不添加 Agent、审批服务、Decision 级摘要或新状态机；不为缩字数删除完整 Schema、状态机和主流程。复杂度判断仍由对话和用户批准管理，不把 flag 宣称为身份认证。

文本摘要不能识别语义等价；冻结后不做无关润色。仅验证表格完整性和非占位，不声称机器已证明 AC 或测试陈述真实。

## 验证方法

现有全量回归继续覆盖确认门、摘要漂移、attempt、依赖基线、worktree、安装清理及回滚；新增模板生成、初始化修复和证据反例。CI 同时执行 Python 3.11 / 3.13、角色配置、安装 dry-run、Mermaid、Docker fixture 和固定版本 Codex fixture。

首轮 CI 发现精简提示词时遗漏既有叶子 features 开关；已恢复原配置，不通过放宽校验绕过。此记录不预填通过次数，具体结果以最终提交对应 CI 为准。fixture 不代表用户环境部署或真实模型质量。

## 第一方依据与取舍

- [OpenSpec 概念](https://github.com/Fission-AI/OpenSpec/blob/main/docs/concepts.md)：区分变更增量与长期规格，归档后同步事实；不照搬其全部工件链。
- [Spec Kit SDD](https://github.com/github/spec-kit/blob/main/spec-driven.md)：明确约束、可验证要求与需求到测试的联系；不照搬库优先等不适合所有工程的预设。
- [Kiro Feature Specs](https://kiro.dev/docs/specs/feature-specs/)：用条件、触发和系统行为表达验收；不强制为每项需求生成设计文档。
- [Codex AGENTS.md](https://developers.openai.com/codex/guides/agents-md)、[Skills](https://developers.openai.com/codex/skills)：长期指令与按需技能分层；本包继续保留自己的权限/运行时验证边界。

这些是实践参考，不是统一认证标准。验收标准是本项目要求和真实运行证据，而不是文件数量或模型级别。
