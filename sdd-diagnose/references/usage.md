# 诊断包

## 使用

在发生问题的项目中输入 `$sdd-diagnose`，或“生成当前项目的诊断数据包”。技能只运行 Node.js 打包入口；不增加诊断模型或子代理。读取技能、调用命令和返回路径本身仍会使用当前对话上下文，不声称绝对零 Token。

默认最近 7 天、最多 20 个根 turn，不将它们自动视为同一需求。收集进行中的 turn 时会标记覆盖不足。根据实际时间选最近记录，不根据任务标题或对话文本猜测关联。

可选参数：`--days 1`、`--limit 50`、`--output /private/location/report.zip`、`--expected-mode sdd --expect-role explorer`。只有操作者明确给出期望时，才运行相关适用性检查；默认 unknown。

## 包内容

| 文件 | 内容 |
| --- | --- |
| summary.md | 片段统计、诊断摘要与覆盖边界 |
| reports/*.md | 每个片段的既有确定性诊断报告 |
| data/*.json | 归一化执行、委派、关联 SDD 状态、指标和证据位置 |
| inventory.json | 当前 AGENTS/角色/Skill 的指纹，不是正文副本或历史加载证明 |
| manifest.json | 选择范围、截断/缺失计数、文件校验值 |
| README.md | 阅读顺序、隐私与诊断限制 |

包默认保存在 CODEX_HOME/sdd-observe/bundles/，未设置 CODEX_HOME 时为 ~/.codex；ZIP 权限 0600。禁止写进业务项目或 Git 树，不覆盖已有文件，不上传、不复制原始记录、源码或完整配置，不改观察数据库或业务状态。

## 缺失与边界

`no_sessions` 仍会生成包含当前规则指纹和缺失说明的包，不谎称已检查执行。先确认是在发生问题的项目中运行、Codex 已保留本地 sessions；不自动安装软件或读取其他项目正文。

默认只扫描 sessions，归档目录可由 `--sessions-dir` 指定。扫描上限：10000 个日志文件、最近 200 个项目根会话、合计 300 个完整 trace、原始 trace 累计 128 MiB；ZIP 原始内容上限 32 MiB。达到扫描限制必须标记 partial，明确显示未纳入的片段数；超出导出大小则失败，不静默丢数据。

仅复用现有观测器支持的格式，不执行日志里的命令，不调用 Codex/网络/模型。普通测试、真实模型质量、文档是否足以实现和提示词语义，不由固定规则自动判定。
