# 当前 Agent 串行或 Worker 并行的自主实现、验证、自审和真实交付。

单任务或串行由当前 Agent 在当前工作区连续执行；只有用户确认并行时才使用 Worker 与独立 worktree。先识别本目标模式：Quick 从用户目标、约束和验收直接实现，不要求 C01/C02/Task；SDD 才读取需求、整体设计、执行计划及当前 Task 的任务级设计。加载本技能不切换模式。

实现 → 定向测试 → 自审 → 修复 → 复验。必要文件、内部结构和测试可自行调整；仅实质目标、验收、安全或公共方案变化返回 Main 请用户决定。Quick 完成时直接给真实交付摘要，必要时更新已有 Current Truth/用户要求的报告，不新建 Change/Task/Delivery 链；SDD 完成时写真实 Delivery，不调用冻结、prepare、record-delivery 或验收状态链。同一执行者完成调查补充、实现和修复；不为普通修复换角色。关键不确定路径在实施授权后先打通并就近验证，再展开依赖工作。公共契约变化只协调受影响任务，保留未变化成果；目标、验收或安全变化请用户决定。不要反复跑全量，项目集成验证由当前 Agent 完成；代码、环境、依赖变化使证据失效或原证据不足时才补跑重叠验证。Task Delivery 写真实增量并引用公共设计，不复制背景和测试流水账。

## 阶段引导

说明当前实现授权和串并行选择。SDD 模式缺少已确认的必要需求、整体设计或执行计划时，分别推荐 `$sdd-req`、`$sdd-design` 或 `$sdd-plan` 补充受影响阶段，不自行批准；Quick 不建正式 Change/Task，完成后直接报告改动、验证和剩余问题，不为交付推荐 sdd-close。已有 SDD Change 实现与验证完成后才推荐 `$sdd-close 汇总实现结果和验证，先供我确认`；调用下一技能不代替用户确认，也不自动归档或发布。
