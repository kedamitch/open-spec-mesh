# 审查清单

Worker Delivery / 自审是待验证声明；以 Contract ↔ Diff ↔ Tests 为主要证据。先检查需求符合性（缺失 / 多做 / 做错），再检查相关质量项：

| 维度 | 核对重点 |
| --- | --- |
| 正确性 | 业务逻辑、边界、空值、异常路径、状态转换 |
| 数据 | 事务、幂等、并发竞争、一致性、历史数据 |
| 安全 | 鉴权、权限、输入、注入、敏感信息 |
| 性能 | 高频路径、IO/查询、锁、内存和资源泄漏 |
| 兼容性 | API、协议、配置、Schema 的前后兼容 |
| 可靠性 | 超时、重试、降级、失败恢复、资源释放 |
| 可维护性 | 重复、复杂度、耦合、现有架构约束 |
| 测试 | 正常、异常、边界和回归是否真正被断言 |

只报告与本次改动和指定风险有关且有证据的问题：位置 → 影响 → 建议验证。区分 blocker / risk / unverified；风格偏好不阻断，不扩大成全仓审计。
