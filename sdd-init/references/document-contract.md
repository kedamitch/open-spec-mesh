# 文档契约

文档首先服务人类评审，工具辅助而不控制授权。完整保留 docs/01–09、C01/C02/C03、独立 Task、Delivery 与导航，沿用英文文件名、中文正文；结构完整不等于内容重复。模板按实际需要展开，不要求空章节、固定字段或每个 Task 图表。

Quick 不建立本节的 Change/Task/Delivery 链；仅按实际影响更新已有 Current Truth，或按用户要求写必要报告。完整结构保留针对既有文档和明确采用 SDD 的目标，不是所有任务的前置负担。单任务 SDD 短写见[示例](single-task-example.md)。

## 信息职责

- Current Truth：产品、架构和运维的实际完整现状，随已实施事实同步；人工验收状态单列，不等同源码是否实现。
- C01 Change：背景、目标、范围、不做事项、可观察 AC、限制与人工阶段确认。
- C02 Design：整体方案、必要模块职责、关键流程、公共约定与风险；不预列所有文件/函数。
- C03-tasks/C03-task-plan.md：执行计划，说明任务拆分、依赖、集成验证与用户确认的串并行方式，不存机器执行状态。
- 独立编号 Task 目录：记录任务级设计，包括宏观目标、业务范围、输入/依赖、交付输出、总体方向、验收与验证策略；公共方案与背景引用 C01/C02，只补本任务差异；短写也保留可执行目标、约束和验收，不能只留链接。
- Delivery：真实改动、验证、自审与重要调整、剩余问题、快照影响；完成时创建，不提前生成空报告。Task Delivery 记录实际增量；整体交付汇总跨任务结果和集成验证，引用而不复制所有报告。
- ADR / Research：长期决策/可复用证据，不保存搜索流水账。
- Quality / Release：真实检查结果、版本变化和发布准备，不能代替测试或真正部署。
- index.md：Purpose、Documents、Navigation，不复制正文。

## 阶段确认

需求 → 设计 → 执行计划 → 实现 → 交付，每阶段等用户明确确认；用户可明确连续授权多阶段。C01 记录日期、明确指令与对象，Git 可辅助追溯但不要求签名或摘要。修改意见、Agent 自审和工具通过不是确认。局部实现调整由执行者决定；目标、验收、安全或重要公共方案变化才请用户决定；内部文件/函数调整自行处理，任务间契约变化只协调受影响任务，保留未变化成果。

## 写作与校验

目录、编号、章节、表格与链接检查是辅助建议；不能因未来工件尚不存在或格式变化卡住当前阶段。真实语义缺口由 Agent 解释，测试与安全失败仍必须处理。文件路径可作定位，不作 allow/deny 清单。历史 Graph 只读保留，新流程不生成 Graph、digest、attempt、receipt 或审批 token。

图表在有助理解时使用；简单 Task 短写。没有核实的内容明确未知；Delivery 可记录未通过，但不得伪造全部通过。
