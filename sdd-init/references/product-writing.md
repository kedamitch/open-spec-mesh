# 产品 Current Truth 写作规范

产品 Current Truth 必须让没有参与本次迭代的人理解：**产品服务谁、有哪些模块、各模块做什么、用户如何完成主流程、有哪些跨模块规则。**

## P01-product-overview.md

必须包含：

1. **产品定位与边界**：服务对象、核心目标、明确不做事项。
2. **用户与核心场景**：角色、场景、目标。
3. **产品架构**：引用 `P03-diagrams/P03-01-product-architecture.md`，表达业务目标 → 场景 → 模块 → 共享能力。
4. **模块总览**：模块职责、核心能力、主要场景、详细文档。
5. **核心业务流程**：引用 `P03-diagrams/P03-02-main-user-flow.md`。
6. **跨模块业务规则**：权限、状态、数据口径、通知/交互等共享规则。
7. **外部系统**：用途和交互边界。

## P02-modules/P02-xx-<module>.md

每个真实模块至少维护：

### 模块定位
- 使用者。
- 职责。
- 边界。
- 与其他模块关系。

### 核心能力 / 功能清单

| 功能 | 入口 / 触发 | 主要规则 | 成功结果 | 失败 / 拒绝 |
| --- | --- | --- | --- | --- |

### 用户流程

复杂流程优先 Mermaid；简单流程用短列表。

### 业务规则
- 权限与角色。
- 状态及转换。
- 数据口径。
- 幂等 / 重复操作。
- 失败与恢复。

### 页面与交互（有 UI 时）
- 入口。
- 关键操作。
- 加载 / 空 / 失败状态。
- 关键确认与反馈。

### 依赖与技术关联
- 依赖模块。
- 相关领域模型。
- 相关 API。

没有对应复杂度时删除可选小节，不机械凑模板。

## 产品图表

- `P03-01-product-architecture.md`：真实能力分层和模块关系。
- `P03-02-main-user-flow.md`：用户从目标到业务结果的主流程。

图里出现的模块必须能在模块清单找到；模块新增/删除/职责变化时同步更新图和正文。

## Change 与 Current

- Current Truth 保存**当前完整产品行为**。
- Change 只写增量需求和 AC。
- Design 按 **Current → Delta → Target** 说明本次产品变化。
- 验收集成后再把已实现变化同步回 Current Truth。
