# 单任务 SDD 短写示例

仅用户明确选择 SDD 时参考；不是 Quick 的必写模板，不增加阶段或代理。下面是假想“规范化读取”示例，验证结果不能复制为真实通过。

| 工件 | 最小可执行内容 | 不重复的内容 |
|---|---|---|
| C01-change.md | 目标：读取键忽略字符串大小写/空格。约束：缺失仍undefined。验收：同一键写读相等、缺失兼容。记录真实授权范围。 | 不写函数/文件计划 |
| C02-design.md | 约束：共享键语义不变。可调：内部实现组织。假设：读写可复用现有规范化逻辑；授权内先最小核验。 | 不再抄背景与验收全文 |
| C03-task-plan.md | 1个Main串行Task，无依赖；输入已有实现；输出修复/测试；Main负责集成验证。 | 不抄Task方案或派发包 |
| 独立Task | 可执行目标：补齐读取规范化并保持缺失契约。输入引用C01/C02；方向是复用已核实公共语义；定向验证同键/缺失/边界。 | 不穷举函数、文件或编码步骤 |
| Task Delivery | 写实际增量、实际定向验证结果、调整及剩余风险，未运行写未运行。 | 不抄设计背景或完整日志 |
| C04-delivery.md | 汇总结果、Main集成检查、Current Truth变化与待人工确认；引用Task Delivery。 | 单任务可很短，不再复制其报告 |
| index.md | 自动维护可定位导航 | 不复制正文 |

Task不能只有一个链接：短写仍保留执行者能直接理解的目标、约束与验收。路径仅定位，不是权限清单。重要变化按影响范围协调，不重做未变化工件。实际源码现状随实施同步；最终验收/归档仍遵守用户授权，明确的一次关闭授权不强制拆成两轮。
